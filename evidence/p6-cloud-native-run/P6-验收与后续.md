## 二、内容问题与证据定位

### 1. 四岗位职责尚未充分转化为业务成果

`decoded/leader/request.json` 的 roleQuestions 要求事实时间线、方案矩阵、关系与授权图、观众影响及执行清单等共 13 个命名交付项。但本轮主要产物是统一 receipt / facts / conflicts / unknownFields；没有这些独立业务交付文件。不能用旧 p1b 的完整交付物补进 p6 再称为本轮产出。

第二岗 `decoded/02/receipt.json` 主要复述事实缺口，尚未形成按方案列出的“条件—阻断—截止—所需人类确认—失败转移”比较。第三岗发现了身份与权限缺口，但尚未形成可核查的关系/许可登记表。第四岗缺少充分展开的观众损失、沟通文案和执行准备清单。

这与本地对应运行时代码 `src/dsh-runner.mjs` 中偏向活动入库、证据核验和实体匹配的通用 rolePolicies 相吻合。下一轮部署前还应核对镜像内实际提示词，不能只改页面上的岗位名称。

### 2. 模拟条件被当作整段推演的阻断理由

第二、四岗及 Leader 均强调合成晚到信息不能用于真实业务；这个安全边界正确。但第四岗和 Leader 进一步将其排除在截止时间、合排条件判断之外，削弱了反事实推演。

应明确区分：模拟条件可以参与标注清楚的“如果……则……”演练计算；它不能变成历史事实，也不授予任何真实行动权限。未知事实、口述争议、模拟假设应分别列账，而不是都变成停止推演的理由。

### 3. 本轮闭源库与来源正文输入不足

`decoded/leader/request.json` 的 inputPayload 包含 incident、factClaims、options、stakeholders、lateArrivalFacts、humanDecisionBoundary、roleQuestions 等；没有完整的 virtual-private-library 和权限矩阵输入。

第二、三、四岗 input.json 中的 sourceManifest 显示 sourceLocators 为空、sourceArtifactSha256 为 null。引用来源标识不等于实际拿到了文章正文、访谈原文或合同摘录。

本轮可展示“Agent 主动识别缺口”，但不能声称本轮已经实测闭源库的“允许读取 / 仅元数据 / 不可见 / 禁止批准”四种权限路径。旧本地预验证中的此类成果仍可对照展示，来源必须分开。

### 4. 部分判断内部不一致或因果依据不足

- 第四岗与 Leader 在分析前段称转播覆盖已确认，后段又称其仅部分验证、原文不可核实。应保留为冲突，不能挑有利段落当结论。
- 第二岗把医嘱休息小时数不一致联系到替补通知窗口、退款时效依据，输入中未见足够因果支撑。医嘱具体时长存疑，不自动说明其他独立方案无法比较。
- 第一岗一面承认输入是零真实写入的演练包，一面称是否允许生产摄入未明确。输入 publicWriteAllowed=false 已经明确，不能凭此制造新的“需人确认才能继续分析”的阻塞。

这些问题已经保留在原件与页面原文中；本次没有篡改原始输出使其显得更好。
