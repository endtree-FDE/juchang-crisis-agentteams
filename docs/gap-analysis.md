## 一、硬性指标对照（必须达成，否则一票否决）

| 硬性要求 | 现状 | 判定 |
|---|---|---|
| 基于 AgentTeams 框架的协同流程（角色编排/任务拆解/上下文传递/状态追踪） | cloud dispatch/receipt 合同 + 四岗 DAG + 验收链真实存在 | ✅ 达标 |
| ≥3 个不同职能 Agent | 四岗 + Leader，职责边界与权限合同化 | ✅ 达标 |
| 核心 Skill 清单（用途/输入输出/调用条件/失败处理/安全边界/复用价值） | 只有 Skill **候选**（治理演示用），P1 真实运行中 skillInvocations 为空（当时为诚实而省略） | ❌ **高危缺口** |
| 可运行验证（含高风险操作人工确认/回滚/审计） | test:crisis-sim 16/16、check/build、回放导出门禁、人工收据 | ✅ 达标 |

**红线警告（规则原文）**：
- 「复赛未提供任何核心 Skill，或核心 Skill 完全没有可运行实现：建议列为全局一票否决。」
- 「核心结果通过硬编码或模拟返回，却宣称来自真实 Skill 执行：全局一票否决。」
- 「以单 Agent、固定脚本或模拟事件冒充 AgentTeams 多 Agent 运行：全局一票否决。」——我们的 P1 是 DSH 本地会话真实模型调用，诚实标注了非云端；但要拿高分，应补一次**云端 AgentTeams Runtime（Matrix/Taskflow）权威运行**。
- 「关键效果、测试、Trace 或运行证据被证实伪造：全局一票否决。」——我们的诚实分层纪律正是为此设计，保持。

## 三、演示叙事重构（用户指示：收到一个消息 → 开始各种跑 → 各种 trace）

```
0. 空态：知识库/闭源库就绪，无活动案件
1. 消息降临：演练入口从「按钮」改为「收到一条现场消息」
   （舞台监督发来的消息卡片：钢琴家病倒。消息即案件创建事件，带 trace 起点）
2. 各种跑：四岗 DAG 真实推进 + 每岗的 trace 流可见
   （任务派发/接单/读取闭源库/调用 Skill/提交回执/Leader 验收——逐事件滚动）
3. Skill 真实调用：可行性岗调用 artist-substitution-feasibility@x.y.z，
   trace 记录 skill 版本、输入摘要、输出结论、耗时
4. 异常注入：晚到事实到达（决策包后信息）+ 一条闭源库读取被拒转人工
5. 停在人工：炸弹倒计时继续走，具名人类决定，收据绑定真实运行哈希
6. 复盘：Skill 新候选登记（治理口径不变）、安全计数四零、回放冻结
```

Trace 抽屉（演示中可展开）：同一 runId 关联 派单→任务事件→角色回执→Skill 调用→人工收据→回放哈希，全链可点。
